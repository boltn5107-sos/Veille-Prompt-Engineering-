Prérequis sur les LLM
NotionDéfinition & impact pratique
LLMModèle entraîné à prédire le mot suivant sur des milliards de textes. Il ne « sait » pas : il calcule des probabilités.
ContexteEnsemble du texte déjà présent (prompt + conversation). Tout tourne autour de lui : plus il est clair, plus la réponse est juste.
TokenUnité de base du texte (mot, partie de mot, ponctuation). 100 tokens ≈ 75 mots. Tout coûte des tokens.
Fenêtre de contexteNb max de tokens visibles (entrée + sortie). Ex. 8k ≈ 6 000 mots. Au-delà : texte oublié ou refusé. → ranger les données utiles en premier.
TemperatureHasard. 0.0–0.3 = fiable/répétitif ; 0.7–1.0 = créatif/varié.
max tokens / top-p / top-kmax tokens = longueur de sortie ; top-p (0–1) et top-k ne gardent que les choix probables. Faibles = déterministes.
stop sequencesChaînes qui coupent la génération (fin de JSON, balise, séparateur).
Règle : tâche précise → temperature 0,2  |  tâche créative → temperature 0,8  |  toujours prévoir assez de max tokens pour finir la réponse.

Introduction au Prompt Engineering

QU'EST-CE QU'UN PROMPT ?

Un prompt est l'instruction donnée à l'IA : question, ordre, texte à transformer, contrainte. C'est la seule façon de « piloter » le modèle.

PROMPT ENGINEERING

Discipline = concevoir, tester, améliorer des prompts pour des réponses précises, fiables et exploitables. Pas du code : une méthode de rédaction.
POURQUOI C'EST IMPORTANT
Qualité : une bonne formulation peut doubler la pertinence d'une réponse, sans changer de modèle.
TEMPS GAGNé
Moins d'aller-retours et de corrections, résultats exploitables du premier coup.
PASSAGE À L'ÉCHELLE
Industrialiser l'IA dans les applications métier : formats fixes, automatisation, contrôle.

Zero-shot prompting
OBJECTIF — pourquoi ?
Tâche simple et connue du modèle : nulle besoin d'exemple, un ordre clair suffit. Rapide, économe en tokens.
SYNTAXE — comment ?
Décrire la tâche au verbe d'action, puis fournir l'entrée. « Fais X sur Y. »
EXEMPLE
« Classe le sentiment de ce commentaire (positif / négatif / neutre) : « Le produit est arrivé cassé. » » Sortie : Négatif (fiable dès l'entraînement).

One-shot prompting
OBJECTIF — pourquoi ?
Montrer le format attendu d'un seul exemple : le modèle copie structure et style. Idéal pour un format inhabituel.
SYNTAXE — comment ?
Tâche + 1 exemple (entrée -> sortie) + nouvelle entrée. L'exemple sert de moule.
EXEMPLE
Convertis un titre de film en emojis. Exemple : « Jaws » -> [requin][vague] « Titanic » -> ? → [bateau][glace][triste]

Few-shot prompting
OBJECTIF — pourquoi ?
2 à 5 exemples enseignent le « schéma » (format + logique). Grande précision sur les tâches inhabituelles ou nuancées.
SYNTAXE — comment ?
Tâche + série d'exemples A -> B + nouvelle entrée terminée par une flèche pour signaler la suite.
EXEMPLE
Classe : Travail / Personnel / Spam « -50% ce week-end ! » -> Spam « Budget Q2 ? » -> Travail « Recette de grand-mère » -> ? → Personnel

Chain-of-Thought (CoT)
OBJECTIF — pourquoi ?
Forcer le raisonnement étape par étape : améliore fortement le calcul, la logique et la réduction des erreurs de chiffres.
SYNTAXE — comment ?
Ajouter une invitation explicite : « Raisonne étape par étape avant de répondre. » (version « seed » du paper Wei et al. 2022).
EXEMPLE
Train A : Paris 9h à 120 km/h. Train B : Lyon 9h à 90 km/h. Distance : 470 km. « Raisonne étape par étape. » 1) temps relatif t = 470/(120+90) = 2,24h 2) rencontre à 11h14.

Structured prompting
OBJECTIF — pourquoi ?
Sortie contrainte à une structure = exploitable par un programme : JSON réinjectable, zéro reformatage.
SYNTAXE — comment ?
Imposer le format dans le prompt, fournir un squelette, bannir le texte autour : « Réponds uniquement en JSON. »
EXEMPLE
{ "resume": "en 1 phrase", "mots_cles": ["3 à 5"], "tone": "neutre", "score": 0.0 … 1.0 } Niveau supérieur : JSON schema (codes), validation automatique.

PE et raisonnement

DÉCOMPOSITION — « diviser pour régner »

Casser un problème complexe en sous-tâches simples. Chaque sous-tâche est fiable ; on assemble ensuite les résultats (ou on délègue à un sous-agent). 1) extrais produits + prix 2) calcule chaque marge 3) classe par marge décroissante

SELF-CHECK — le modèle se relit

Générer, critiquer, corriger : 1) proposer une réponse 2) lister 3 erreurs ou oublis 3) écrire la version corrigée Variante « double-pass » : une critique indépendante, puis fusion des deux réponses.
Leçon : sur toute tâche à plusieurs étapes, exiger la décomposition AVCANT la réponse finale — c'est le cœur du raisonnement maîtrisé.

Prompts pour les applications métier
ApplicationPrompt « type »Pourquoi ça marche
Résumé« Résume en 3 puces en gardant les chiffres clés. »Longueur + point d'ancrage
Traduction« Traduis en anglais pro, garde nombres et ponctuation. »Registre explicite
Classification« Classe ce ticket : bug / question / feature. »Catégories closes
Extraction« Extrais nom, date, montant. Réponds en JSON. »Format imposé
Génération« Mail de relance, 150 mots, ton courtois, date limite + réf. facture. »Public + ton + détails
Code« Fonction Python (moyenne d'une liste), avec docstring et cas vides. »Spécifications précises
Règle d'or : toujours préciser public + longueur + ton + format. « Un mail » ≠ « une relance de paiement au fournisseur X, 150 mots, ton courtois, avec la date limite et la référence facture ».

Prompts pour le Machine Learning
PRÉPARATION DES DONNÉES
« Nettoie ce jeu de données : supprime les doublons, corrige les valeurs abérantes, normalise dates, et rends un tableau des corrections. »
GÉNÉRATION DE VISUALISATIONS
« Code matplotlib d'un histogramme du CA mensuel à partir de ces données, étiquettes en français, 800×500. »
SÉLECTION DE MODÈLES
« Classification d'e-mails spam / non-spam : 10 000 exemples. Compare 3 familles de modèles et recommande, en arbitrant précision / coût / simplicité. »
INTERPRÉTATION DES MÉTRIQUES
« Matrice de confusion : précision 0,72, rappel 0,88. Qu'est-ce que cela signifie en dépistage médical (FP/FN) ? Propose 2 améliorations. »
ASTUCE
Demandez TOUJOURS le code ET l'explication : on récupère l'exécutable + le raisonnement pour vérifier.

Prompt Engineering et RAG
Pourquoi le prompting seul ne suffit pas : le LLM ignore vos documents internes et l'actualité, et peut halluciner sans source.
1. RECHERCHE
Indexer la base de documents, retrouver par similarité les passages pertinents pour la question (retrieval / embeddings).
2. AUGMENTATION
Insérer les extraits retenus DANS le prompt, mélangés à l'instruction et à la question.
3. GÉNÉRATION
Le modèle répond UNIQUEMENT sur ces extraits, avec citation du ou des documents sources.
« Réponds UNIQUEMENT à partir des extraits ci-dessous. Si absent : "Information introuvable." Extraits : <<<doc1 : …>>> <<<doc2 : …>>> Question : … 200 mots max, cite les sources. »

Évaluation et optimisation des prompts
POURQUOI ÉVALUER ?
Un prompt qui « marche une fois » peut échouer sur d'autres entrées. Mesurer = comparer en connaissance de cause, avant de déployer en prod.
MESURER LA QUALITÉ
Critères : exactitude, exhaustivité, format, ton, absence d'hallucination. Méthodes : grille manuelle, jeu de test fixe, notation par un autre LLM (LLM-as-judge), F1 / concordance.
OPTIMISATION ITÉRATIVE
boucle : écrire → tester sur Méme échantillon → identifier erreurs → corriger → re-tester. Comparer par A/B : 2 prompts sur les MÊMES entrées. Versionner chaque prompt (v1, v2…).

Limites et risques
RisqueDescriptionMitigation
HallucinationFait faux présenté avec assuranceRAG + citations + validation humaine
AmbiguïtéPrompt flou → réponse au hasard ou hors-sujetPréciser, reformuler, tester 2 versions
BiaisStéréotypes présents dans les données d'entraînementPrompts neutres, jeux de cas sensibles, relecture
ConfidentialitéLes données envoyées peuvent être stockéesNe jamais envoyer de données sensibles ; anonymiser
Injection de promptDes données utilisateur détournent les instructionsSéparer instructions/données, filtres, validation
JailbreakContournement des garde-fous de sécuritéFiltres de sortie, supervision, mises à jour
Le prompt engineering ne supprime pas les risques, il les réduit. Supervisez toujours les décisions importantes.

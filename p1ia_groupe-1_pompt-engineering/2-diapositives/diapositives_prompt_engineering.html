1
Prérequis sur les LLM
  • LLM = prédit le mot suivant, entraîné sur d'énormes volumes de texte
  • Contexte = tout le texte déjà présent (prompt + conversation)
  • Token = unité de base (100 tokens ≈ 75 mots)
  • Fenêtre de contexte = taille max en tokens (entrée + sortie)
  • Temperature = hasard (0 fiable → 1 créatif)
  • max tokens = limite de longueur de la sortie
  • top-p / top-k = filtrent les choix probables
  • stop sequences = arrêt automatique de la génération
2
Introduction au Prompt Engineering
Un prompt = la seule façon de piloter un LLM
  • Prompt = instruction donnée à l'IA (question, ordre, texte à transformer)
  • Prompt Engineering = concevoir, tester, améliorer les prompts
  • Pourquoi ? qualité des réponses, temps gagné, moins d'erreurs
  • Permet d'industrialiser l'IA dans les applications métier
3
Structure d'un prompt

RÔLE

qui est le modèle ?
ex. expert CA

CONTEXTE

situation, public, limites

TÂCHE

verbe d'action
« résume », « classe »

DONNÉES

le texte à traiter, bien délimité

CONTRAINTES

longueur, ton, style, interdits

FORMAT

JSON, puces, tableau...

Tu es un analyste financier. → RÔLE Synthèse pour un PDG non technique. → CONTEXTE Résume ce rapport trimestriel. → TÂCHE Rapport : <<<texte>>> → DONNÉES Max 8 lignes, sans jargon. → CONTRAINTES Format : 3 puces + 1 conclusion. → FORMAT
4
Zero-shot prompting
OBJECTIF (pourquoi ?)
Aucun exemple donné. Le modèle mobilise directement son entraînement.
SYNTAXE (comment ?)
Décrire la tâche + fournir l'entrée. « Fais X sur Y ».
EXEMPLE
« Classe le sentiment de ce commentaire (positif / négatif / neutre) : « Le produit est arrivé cassé. » »
4
One-shot prompting
OBJECTIF (pourquoi ?)
Un seul exemple montre au modèle le format ou le style attendu.
SYNTAXE (comment ?)
Tâche + 1 exemple (entrée -> sortie) + nouvelle entrée.
EXEMPLE
Convertis un titre de film en emojis. Exemple : « Jaws » -> [requin] « Titanic » -> ?
4
Few-shot prompting
OBJECTIF (pourquoi ?)
2 à 5 exemples : le modèle apprend le « schéma » et l'applique.
SYNTAXE (comment ?)
Tâche + exemples A -> B + nouvelle entrée -> ?
EXEMPLE
Classe : Travail / Personnel / Spam « -50% ce week-end ! » -> Spam « Budget Q2 ? » -> Travail « Recette de tarte » -> ?
4
Chain-of-Thought (CoT)
OBJECTIF (pourquoi ?)
Imposer un raisonnement pas à pas pour fiabiliser les réponses.
SYNTAXE (comment ?)
Ajouter « Raisonne étape par étape » à la fin du prompt.
EXEMPLE
Train depuis Paris : 120 km/h. Train depuis Lyon : 90 km/h. Distance : 470 km. « Raisonne étape par étape. »
4
Structured prompting
OBJECTIF (pourquoi ?)
Sortie contrainte à un format = exploitable par un programme.
SYNTAXE (comment ?)
Imposer le format dans le prompt : « Réponds uniquement en JSON, sans texte autour. »
EXEMPLE
{ "resume": "...", "mots_cles": ["..."], "confiance": 0.9 }
5
Prompt Engineering et raisonnement
2 techniques d'or pour la logique et la synthèse
  • Décomposition : découper un problème complexe en sous-tâches simples
  • Chaque sous-tâche est traitée séparément, puis on assemble
  • Self-check : le modèle relit, critique puis corrige sa propre réponse
  • Double-pass : réponse 1 → critique → réponse 2 corrigée
6
Sorties structurées
  • Pourquoi ? exploitation automatique, comparaison, moins d'oublis
  • JSON : passage aux applications (API, automatisation)
  • XML : documents, échanges normalisés
  • Tables Markdown / CSV : exports Excel
  • Validation : le code vérifie le format ; le modèle relit face au schéma

Prompts pour le Machine Learning
  • Préparation : nettoyage, doublons, normalisation des dates
  • Visualisation : demander le code matplotlib adapté aux données
  • Sélection de modèles : faire comparer plusieurs familles de modèles
  • Interprétation : expliquer matrice de confusion, précision, rappel
9
Prompt Engineering et RAG
Le prompting seul ne suffit pas : le modèle ignore vos documents et l'actualité.
1. RECHERCHE
Chercher les passages pertinents dans une base de documents (retrieval).
2. AUGMENTATION
Insérer ces extraits dans le prompt.
3. GÉNÉRATION
Le modèle répond uniquement à partir des extraits cités.
« Réponds UNIQUEMENT à partir des extraits ci-dessous. Si absent : "Information introuvable." Extraits : <<>> <<>> Question : ... 200 mots max, cite tes sources. »
10
Évaluation et optimisation des prompts
  • Pourquoi : un prompt « qui marche une fois » peut échouer ailleurs
  • Mesurer : exactitude, exhaustivité, format, absence d'hallucination
  • Comparer : A/B testing sur les mêmes entrées, grille de notation
  • Itérer : écrire → tester → repérer les erreurs → corriger → re-tester
  • Versionner : garder les versions (v1, v2, ...)
11
Limites et risques
  • Hallucinations : réponses fausses mais assurées  →  RAG + citations
  • Ambiguïté : prompt flou = réponse au hasard  →  préciser tout
  • Biais : stéréotypes reproduits  →  relecture humaine
  • Confidentialité : les données partent chez le fournisseur  →  anonymiser
  • Injection de prompt : les données détournent les instructions  →  séparer
  • Jailbreak : contourner les garde-fous  →  supervision
